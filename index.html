Release rule

A workflow moves from roadmap to ready only when its intended host shows the expected result, every consequential claim has an authorized citation, negative paths fail closed, telemetry is attributable, and source effects match the approved boundary.

Where Azure fits

Secure execution behind the experience

Azure is the reference execution layer for the current release. It is not a second user interface, a data warehouse, or a replacement for Dynamics 365.

1. Experience

Microsoft Copilot and Sales

Conversation, confirmation, citations, user assignment, and admin governance.

2. Extension package

Agent, policy, and API contract

Instructions, one bounded tool, OAuth reference, response semantics, and version identity.

3. Customer-owned bridge

Azure reference implementation

Single-tenant authentication, on-behalf-of token exchange, bounded reads, denial handling, Key Vault, and telemetry.

4. Systems of record

Dynamics 365 and future providers

Records remain protected by each signed-in user's permissions and provider-owned identity.

Can Azure be replaced? The current package requires its secure API endpoint. A customer can adapt the bridge to an approved equivalent hosting pattern, but that alternative must preserve the same authentication, authorization, logging, citation, latency, and zero-write tests.

Pilot installation

Customer-owned and intentionally bounded

A tenant-specific package is generated during deployment because the app identity, OAuth registration, backend URL, and Dynamics environment belong to that customer.

  1. Confirm prerequisites.
    Microsoft 365 Copilot, D365 permissions, pilot users, customer admins, Azure landing zone, and one authorized opportunity.
  2. Configure securely.
    Copy the customer template, run fail-closed preflight, and verify tenant/subscription identity before provisioning.
  3. Provision and deploy.
    Create the single-tenant app, OAuth registration, secure evidence bridge, monitoring, and validated donor package.
  4. Assign narrowly.
    Approve the exact package and make it available to specific pilot users, not the whole organization.
  5. Prove the workflow.
    Run two fresh conversations, open all three citations, capture telemetry, and compare records before and after.
  6. Decide and expand.
    Continue, hold, or roll back. Add each new workflow or channel only after its own evidence gate passes.
